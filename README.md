# 照片库总览（OUTPUTWebViewer）

给 `E:\OUTPUT` 这种"按拍摄日期分文件夹"的照片库做一个本地网页：一眼看清每个文件夹多大、里面大概是什么照片。

> **使用者请看 [`使用说明.md`](使用说明.md)**（完整的界面、快捷键、故障排查、性能数据）。
> 本文件偏技术概览。

---

## 怎么用

1. 双击 **`start.bat`**（需要 Node.js，已装过就不用管）
2. 浏览器会自动打开 <http://localhost:7788>
3. 关掉服务：双击 `stop.bat`，或在运行窗口里按 `Ctrl+C`

**手机 / 别的电脑怎么访问**（同一个 WiFi 下）：

- 启动窗口会打印形如 `局域网访问 → http://192.168.1.100:7788` 的地址，网页顶栏也有一个绿色的局域网按钮，点一下就能复制
- 如果别的机器打不开，是 Windows 防火墙拦了。**双击 `开放局域网.bat`**（会弹 UAC 自己提权，逻辑在 `open-lan.ps1` 里）即可放行端口，且**仅限专用网络 / 域网络**
- 只想本机可用：启动前 `set HOST=127.0.0.1`
- ⚠️ **没有登录密码**：同一个 WiFi 下的任何设备都能浏览和下载。家里网络没问题，公共 WiFi 慎用（可以自己套在 Tailscale/ZeroTier 里）

第一次启动扫描约 **1.5 秒**，之后会把结果缓存在 `cache/`，再打开是**秒开**（先显示缓存，同时后台重新扫描）。

想换目录，不用改代码：

```bat
set OUTPUT_ROOT=D:\Photos
node server.js
```

## 界面上能看到什么

**总览页**

- 按年份分组，每行一个日期文件夹：**总大小**、文件数、照片数（JPG / RAW / 视频分别多少）
- 一行细进度条显示该文件夹在整库中的体积占比，一眼看出"哪几个月最占地方"
- 抽样读取 EXIF，显示**相机型号** 和 **拍摄日期**（验证文件夹名是否和实际拍摄时间对得上）
- 点"打开"直接在资源管理器中定位；点整行进详情页
- 支持按日期/大小/张数排序，顶部搜索框可搜年份、文件夹名、相机型号

**详情页**

- 子文件夹各自的体积（比如 `试机/` 下面各机型目录）
- 缩略图网格：同名的 `JPG + RAW` 自动合成一个卡片，不重复占位
- 筛选：全部 / 照片 / RAW / 视频 / 其它
- 点卡片看大图 + 完整 EXIF（机身、镜头、光圈、快门、ISO、焦距、像素）+ 下载原图 + 在资源管理器中定位
- 支持 `←` `→` 翻页、`Esc` 关闭
- **浏览器的前进/后退键可用，且分三层**：总览 → 日期文件夹 → 大图。在大图里按后退就退回网格，再按后退回总览，不会退出网站
  - 地址栏会变成 `#folder=2025-11-12` 或 `#folder=2025-11-12&p=DSC04174`，刷新或分享链接能直接打开那个文件夹 / 那张照片
  - 大图里用 `←` `→` 翻页**不会**堆历史记录（不然连翻 20 张就要按 20 次后退才能出去）

## 关于"缩略图"开关（重点）

工具栏有 `缩略图 关 / 自动`：

| 模式 | 行为 |
|---|---|
| **关**（默认） | 完全不加载图片，页面只有文字和大小，翻页零卡顿。网格里点一下卡片才生成那一张缩略图，再点一下看大图 |
| **自动** | 只加载滚动到屏幕内的缩略图（滚多远加载多远），生成过的会缓存到 `cache/prev/`，第二次就是秒出 |

先用默认的"关"看体积，需要认照片时再切"自动"，或者直接点某几张。

## 缩略图尺寸：小 / 中 / 大 / 特大

旁边的 `小 中 大 特大` 按钮同时控制两处尺寸（选过会记住）：

| 档位 | 总览行封面 | 照片网格卡片宽 | 总览布局 |
|---|---|---|---|
| 小 | 38px | 104px | 紧凑表格 |
| 中 | 60px | 158px | 紧凑表格 |
| **大（默认）** | 200px | 240px | **卡片墙** |
| 特大 | 280px | 340px | **卡片墙** |

选到「大」或「特大」时，总览会自动从一行行表格变成卡片墙（每个日期文件夹一张大图 + 大小/张数/相机），
因为 200px+ 的行高用表格排会很难看。

---

缩略图引擎用的是 **sharp/libvips**（装了的话），没装会自动回退 ffmpeg：

```bat
npm i sharp      :: 强烈建议：快 3~4 倍，内存降 2.5 倍，且能按 EXIF 把砦拍照片摆正
```

启动时会打印当前用的引擎和并发：

```
缩略图引擎: sharp/libvips 8.18.7
CPU: 8 线程 → 并发 小图4 / 大图2
```

并发会**按 CPU 线程数自适应**（低功耗机器如 N4000 会自动降到 2/1，避免卡死）。

## 缓存与内存（实测）

### 磁盘上会留下什么

| 位置 | 内容 | 大小 |
|---|---|---|
| `cache/index.json` | 扫描结果（114 个文件夹 / 39,427 个文件的体积、类型、EXIF 抽样） | 固定 **2.0 MB** |
| `cache/prev/` | 缩略图缓存，**最长边 640px** 的 JPEG | 每张 **24–51 KB** |
| `cache/server.pid` | 进程号，几字节 | — |

- 缩略图只会在你真正浏览过的地方生成；**全部 39,427 个文件都看一遍**大约 **1.2 GiB**
- 上限默认 **2 GiB**，超过会自动删最旧的（可用 `set PREV_CAP_MB=4096` 改）
- 工具栏的 **🧹 缓存** 按钮可以随时查看占用并一键清空
- 点开看大图时（`/api/bigprev`）是**直接抽出来发给你，不写磁盘**
- `cache/` 整个目录随时可以删，删了只是下次浏览重新生成

> 早期版本是把 RAW 内嵌预览原样缓存、JPG 直接发原图，那样会把缓存撑到 **14 GiB**、
> 而且每张给浏览器发 7–48 MB 的原图。现在统一缩到 640px，数据量降到 **1/500**。

### 服务端（node）内存

| 状态 | 内存 |
|---|---|
| 空闲 | **78 MB** |
| 正在扫描磁盘 | **128 MB** |
| 正在生成缩略图（典型 1000–4000 万像素） | 峰值 **331 MB** |
| 正在生成缩略图（极端：4800 万像素原图） | 峰值 **559 MB**，其中 ffmpeg 子进程 ~474 MB |

ffmpeg 解一张 6000×4000 的 JPEG 就要 ~90 MB，9504×6336 要 ~240 MB，这个躲不掉，
所以做了**按文件大小自适应并发**：小于 20 MB 的 4 路并行，大图只开 2 路。缩略图生成完 ffmpeg 立刻退出，内存马上回收。

### 浏览器内存（大概量级）

| 场景 | 占用 |
|---|---|
| 只看总览（缩略图关） | **50–80 MB** |
| 详情页滚动看照片（640px 缩略图，~30 张在视口内） | **150–250 MB** |
| 点开一张看大图 | +**30–250 MB**（看原图大小，关掉就释放） |

按公式说：一张图解码后约 `宽×高×4` 字节。640px 缩略图只有 0.4 MP → 约 1.7 MB；
而 1200 万像素原图是 48 MB，直接铺网格会吃光内存 —— 这也是必须缩到 640px 的原因。

真实占用可以按 `Shift + Esc`（Chrome 自带任务管理器）看当前标签页的“内存占用”列。

## 播放视频时会自动“让路”

4K 视频码率很高（你的片子平均 200 Mbps 全 I 帧），如果后台还在抢 CPU/GPU 生成缩略图，就会卡得动不了。所以：

- **打开视频的瞬间**：浏览器断开网格懒加载 + 取消未完成的图片请求，服务端同时收到 `/api/preview/pause`，**正在跑的 ffmpeg 会被直接 kill**（那一刻 `ffmpeg` 进程数为 0）
- **关闭大图 / 切到纯图片**：自动 `/api/preview/resume`，重新渲染网格继续生成
- 暂停状态下请求缩略图会**立即**返回占位图（不排队、不占连接）
- **不会“卡住不恢復”**：服务端暂停只保留 **30 秒**，前端播视频时每 10 秒发一次心跳续期；
  关标签页 / 刷新时用 `sendBeacon` 立即解除，每次打开页面也会主动 resume 一次
  （曾经出过 bug：暂停是全局开关 + 5 分钟 TTL，放视频时关掉标签页后会导致之后 5 分钟内所有缩略图都是占位图）
- 视频封面抽帧优先用 **Intel QSV 硬件解码**（`-hwaccel qsv` + `hwdownload`），失败才回退软件解码；视频并发限制为 **1**
- 缩略图写入用“临时文件 + 改名”，被 kill 也不会留下半张损坏的缓存

## 技术上怎么做到快的

| 做法 | 效果 |
|---|---|
| 用 Node 原生 `fs` 并行遍历，不用 `du` / `find` | 两万多个文件的全库统计 **16 秒 → 0.5 秒** |
| **RAW 缩略图 = 直接抽取文件内嵌的 JPEG 预览**（纯字节扫描，不解码 RAW） | 每张 7–45ms，ARW/CR3/ORF/RW2 全支持 |
| 后台扫描 + 前端轮询，边扫边显示 | 打开页面立刻有内容，文件夹一个接一个填进来 |
| 扫描结果缓存到 `cache/index.json`（约 2MB） | 二次打开秒开 |
| JPG 直接交给浏览器缩放（本地传输极快），视频用 ffmpeg 抽一帧并缓存 | 不用预先批量生成几十万张缩略图 |
| 自己写的精简 EXIF 解析（JPEG APP1 / CR3 的 CMT1·CMT2 / ORF 的 IIRO / HEIF） | 机身、镜头、日期、曝光参数全都能读到 |

## 目录结构

```
OUTPUTWebViewer/
├─ start.bat            启动（双击）
├─ stop.bat             关闭（只关本工具的进程）
├─ 开放局域网.bat       放行 Windows 防火墙（只需跑一次，会自己提权）
├─ open-lan.ps1         上面那个 bat 的真正逻辑（为了避开 cmd 的编码地雷）
├─ server.js            本地服务器，零依赖（只用 Node 内置模块）
├─ public/index.html    整个前端（单文件，无构建）
└─ cache/               自动生成，可随时删
   ├─ index.json        扫描结果缓存
   ├─ server.pid        运行中的进程号，stop.bat 用
   ├─ port.txt          当前端口，防火墙脚本读它
   └─ prev/             缩略图缓存（640px）+ 大图预览（2048px）
```

> bat 文件全部是**纯 ASCII + CRLF**：cmd.exe 对“含中文的 UTF-8/LF 批处理”会错位解析，
> 报出 `'o' 不是内部或外部命令` 这类怪错。所以中文提示都放进了 `open-lan.ps1`（UTF-8 with BOM，由 PowerShell 处理）。

## 接口一览（想接别的工具也能用）

| 路径 | 说明 |
|---|---|
| `GET /api/state` | 全库统计 + 每个文件夹的体积/文件数/类型分布/相机，扫描中带进度 |
| `GET /api/folder?rel=2025-11-12` | 某个文件夹的完整文件列表 |
| `GET /api/prev?rel=...` | 缩略图（RAW/HEIF/视频自动抽取并缓存） |
| `GET /api/media?rel=...` | 原文件流（支持 Range、ETag，视频可拖进度） |
| `GET /api/exif?rel=...` | 单张照片的 EXIF |
| `POST /api/rescan` | 重新扫描 |
| `GET /api/reveal?rel=...` | 在资源管理器中打开/定位 |

## 已知限制

- 只支持 Windows 资源管理器联动（`explorer.exe`）
- 视频缩略图需要 `ffmpeg` 在 PATH 里；没有的话视频卡片会显示占位图标（其它功能不受影响）
- RAW 用的是文件内嵌的 JPEG 预览，个别机型的内嵌预览分辨率较低（如 RW2 常见 1920×1440），看细节请用"下载原图"或点开 JPG
- MOV 里的 HEVC 视频能否在浏览器直接播放取决于系统解码器，播放不了就用"定位文件"用本地播放器打开
